# TGEveryday — правила работы с кодом

Загружается агентом автоматически: `AGENTS.md` (opencode, Codex, Gemini CLI), `CLAUDE.md` (Claude Code).
Не перечитывай файл перед каждым ответом — считай его активным весь сеанс.
Фактические данные проверены 2026-09-27. При расхождении с кодом — верь коду и обнови этот файл.

---

## 0. ШКАЛА КРИТИЧНОСТИ

| Уровень | Что означает | Что делать |
|---|---|---|
| **КРИТИЧНО** | ломает данные, рассинхрон копий или сборку | остановись, спроси пользователя, не продолжай |
| **ВАЖНО** | нарушает минимальный diff | исправь сам до отчёта, упомяни в отчёте |
| **НОРМА** | стиль, вкусовое | соблюдай по умолчанию |

Не повышай уровень задним числом. КРИТИЧНО — только для: правки JSON-данных, рассинхрона копий,
`build.gradle`/`AndroidManifest.xml`, `AndroidBridge` без задачи, коммита/пуша без запроса,
удаления файла, добавления зависимости.

## 1. ПРИОРИТЕТ ПРАВИЛ (как разрешать конфликты)

1. Явное требование пользователя по текущей задаче.
2. Правило платформы (Android / web) — п.4.
3. Правило двух копий — п.3.
4. Запреты п.2.
5. Стиль и оформление — п.9, п.10.

П.3 сильнее п.4 в одном случае: задача названа «для Android» или «для веба», но правка попадает
в общий файл → общий файл правится в **обеих** копиях, а платформенная специфика внутри него
**не** переносится в другую копию.

П.1 снимает любой запрет, кроме КРИТИЧНОГО. Снятие КРИТИЧНОГО — только после явного подтверждения:
предупреди о конкретном риске и дождись ответа.

## 2. ЗАПРЕЩЕНО

- Добавлять экраны, диалоги, поля ввода, кнопки или логику, которых не просили.
- Рефакторить, переименовывать, реструктурировать без явного запроса.
- Менять или удалять работающий код, если этого не требует задача.
- Трогать `build.gradle`, `settings.gradle`, `gradle.properties`, `AndroidManifest.xml`, если задача не про это.
- Трогать JSON-данные: `timeSchedule.json`, `main_lesson.json`, `extended.json`, `holidays.json`,
  `zanyatiya.json`, `schedule.json`, `template_full.json`.
- Править `timeSchedule.json` «синхронно в двух копиях» — файл расходится намеренно, см. п.3.
- Менять навигацию между страницами (`zayavlenie.html`, `mock-merge.html`, `Nikol/`).
- Менять шутки выходных (`SAT_MESSAGES`, `SUN_MESSAGES`, `renderWeekendMsg`) — пользователь их ценит.
- Менять CSS-переменные и палитры (п.8), если задача не про стили.
- Менять логику уведомлений и импорта/экспорта, если задача не про них.
- Добавлять или менять методы `AndroidBridge`, если задача не про новый мост JS ↔ Kotlin.
- Копировать файл общей логики из одной копии в другую целиком (см. п.3).
- Выдавать обобщённые советы без привязки к конкретному файлу, строке или функции.
- `grep`/`read`/`task` без предварительного `query graph.json` — см. п.6 и п.11.

## 3. ДВУХПЛАТФОРМЕННОСТЬ И ПРАВИЛО ДВУХ КОПИЙ

Проект работает на двух платформах:

- **Web** (GitHub Pages) — `index.html`, `script.js`, `style.css`, `engines.js`, JSON в корне.
- **Android** — Kotlin-обёртка в `android/`, грузит те же веб-файлы из `assets/` через `WebViewAssetLoader`.

Общие файлы существуют в **двух копиях**: корень проекта и `android\app\src\main\assets\`.
Копии **намеренно расходятся** (проверено 2026-09-27):

| Файл | корень | assets | состояние |
|---|---|---|---|
| `script.js` | 1463 стр. | 1773 стр. | **+310 строк** в assets |
| `style.css` | 906 стр. | 961 стр. | +55 строк в assets |
| `index.html` | 136 стр. | 142 стр. | +6 строк в assets |
| `engines.js` | 375 стр. | 375 стр. | идентичны |
| `main_lesson.json` / `extended.json` / `holidays.json` | — | — | идентичны |
| `timeSchedule.json` | 422 стр. | 84 стр. | **разные данные, не синхронизировать** |

Про `timeSchedule.json` в assets — это **минимальный дефолт**, а не копия корневой версии:
`personal` там пустой (`{}`), `custom` содержит только ключи `Кружок по интересам` и `Факультативы`.
Реальные данные пользователя в приложении лежат в `localStorage` (`tg_local_data`) и появляются
после импорта JSON. Поэтому в assets `timeSchedule.json` **не синхронизируется** с корневым.

Правила правки общей логики:

1. Правка вносится **в обе копии точечно**, в то же место, а не перезаписью файла.
2. **Источник истины для Android-логики — assets.** В assets есть Android-специфичные правки
   (импорт/экспорт экранов, рингтон, статусная строка, прогресс-бар), которых нет в корне.
   В web-копии они не нужны и не переносятся.
3. **Источник истины для web-логики — корень.** Обратное тоже верно: web-специфичные правки
   не переносятся в assets.
4. **Никогда** не делай `copy` общего файла поверх копии — затрёшь ~300 строк Android-логики.
5. Перед правкой общего файла — найди целевой фрагмент **в обеих копиях** и убедись, что
   аналогичный фрагмент существует. Если в assets он другой по структуре — правь каждую копию
   по её собственной структуре, а не по подстрочному совпадению.
6. После правки — проверка синхронности (п.6, ШАГ 4) обязательна.

**ОБЩИЙ КОД:** `script.js`, `style.css`, `engines.js`, `index.html`, JSON-дефолты.
**ANDROID-специфично:** `MainActivity.kt`, `NotificationReceiver.kt`, `NotificationHelper.kt`,
`BootReceiver.kt`, `OEMHelper.kt`, `AndroidBridge`, уведомления, выбор звука, оптимизация батареи.
**WEB-специфично:** прямой доступ к DOM, Яндекс.Метрика, PWA, кэширование браузером.

## 4. ПРАВИЛО ПЛАТФОРМЫ

- Задача для Android → решай в `android/`: Kotlin, манифест, ресурсы, assets-копии.
  Веб-корень не трогай, кроме случая, когда правка попадает в общий файл (тогда — п.3).
- Задача для веба → решай в корне: HTML, CSS, JS. Assets не трогай, кроме п.3.
- Задача общая («добавить функцию») → сначала реши, где она живёт:
  - логика отображения/расчётов → `script.js` (общий код);
  - нативная функция (уведомления, файлы, звук) → Kotlin-слой;
  - стили → `style.css` (общий код).
- **Не дублируй логику между платформами.** Если функция в `script.js` — она работает везде.
  Если нужна нативная фича — только в Kotlin.

Связь между платформами:

- JS → Android: `window.Android.methodName(args)`
- Android → JS: `webView.evaluateJavascript("functionName()", callback)`

## 6. РАБОЧИЙ ПРОЦЕСС

### ШАГ 1 — ПОНЯТЬ

- Сформулируй задачу в 1–2 предложениях. Неясно — спроси, **не додумывай**.
- Определи платформу: web / android / общая.
- Определи, попадает ли правка в общий файл → если да, сразу планируй обе копии (п.3).

### ШАГ 2 — НАЙТИ ТОЧКУ ИЗМЕНЕНИЯ

- **Сначала `query graph.json`** (п.11). Без него — `read`/`grep` запрещены.
- По `links` найди зависимости и смежные файлы.
- Только потом `read`/`grep` конкретного файла, ±30 строк вокруг правки.
- Функции в `script.js` громоздкие — ищи по имени функции или ключевым словам
  (в том числе через `query graph.json`), а не построчным чтением.

### ШАГ 3 — МИНИМАЛЬНАЯ ПРАВКА

- Сформулируй diff → выброси всё, что не относится к задаче → финальный код.
- **Критерий приёмки:** ноль изменённых строк вне задачи. Если строка не нужна для результата —
  она не меняется.
- Точно сохраняй оригинальный стиль: отступы, именование, структуру, порядок.
- Не придумывай требования («заодно улучшим»).
- Русские строки — из реальных файлов или существующих кодовых точек, не набирай вручную (п.9).

### ШАГ 4 — ПРОВЕРИТЬ

Обязательные проверки, каждая — с реальным результатом, не «должно работать»:

1. **Синхронность копий** (если правился общий файл) — целевой фрагмент изменён в обеих копиях:
   ```powershell
   Compare-Object (Get-Content script.js) (Get-Content android\app\src\main\assets\script.js) -SyncWindow 5
   ```
   Расхождение в пределах ожидаемого (только android-специфика) — норма. Правка должна
   присутствовать в обеих копиях. Полное совпадение файлов — тревожный признак, что затёрта
   Android-логика.
2. **Синтаксис:** `node --check script.js` (и `engines.js`, `nikol.js` при правке).
3. **Сборка Android:** `gradle assembleDebug` (из `android\`) — только если задача трогает Kotlin,
   манифест или ресурсы.
4. **Кодировка:** файл остался UTF-8 без BOM (п.9).
5. **Сценарий:** мысленно пройти путь пользователя, которого касается правка.
6. **Отчёт:** что изменилось, что проверено, чек-лист ручной проверки (п.10).

## 7. ТЕХНИЧЕСКАЯ СРЕДА

### Web

- Vanilla JavaScript (ES6+), без сборщиков и фреймворков.
- `init()` грузит `timeSchedule.json` (schedule, personal, extended, custom) + `holidays.json`;
  при пустом расписании — fallback на `main_lesson.json` + `extended.json`.
- Глобалы: `SCHEDULE`, `PERSONAL`, `CUSTOM`, `EXTENDED`, `HOLIDAYS`.
- `localStorage`: `tg_local_data` (все пользовательские данные, константа `DATA_KEY` в `engines.js`),
  `tg_edit_mode` (`EDIT_KEY`), `tg_no_defaults`, `tg_reminders`, `theme`, `school`, `personal`,
  `extended`, `custom_<ключ>`.
- В `Nikol/` — отдельное пространство: `nikol_theme`, `nikol_school`, `nikol_personal`,
  `nikol_extended`, `nikol_custom_<ключ>`.
- Аналитика: Яндекс.Метрика, только веб (в Android отключена).

### Цепочка источников данных

1. **Дефолт** — JSON: `timeSchedule.json` (`schedule`, `personal`, `extended`, `custom`).
2. **Перекрытие** — `localStorage` `tg_local_data`. `loadLocalData()` в `engines.js` подменяет
   дефолт, если ключ непустой. В приложении дефолт в assets пустой, поэтому **всё реальное
   содержимое приходит отсюда**.
3. **Импорт** — в Android `importJson` (`MainActivity.kt`) раскладывает файл в `tg_local_data`.
   В вебе импорта нет.

Куда что лежит:

| Что | Источник | Примечание |
|---|---|---|
| Занятия (personal) | `timeSchedule.json` → `personal` | в assets пусто, данные из импорта |
| Экспорт занятий из приложения | имя файла `zanyatiya.json` | `MainActivity.kt`, строка экспорта `personal` |
| `zanyatiya.json` в корне репозитория | **нигде не подключается** | артефакт экспорта; `Nikol/` его тоже не читает |
| Данные для `Nikol/` | `fetch("../timeSchedule.json")` → `data.personal` | `Nikol/nikol.js:456-458` |
| Экспорт из `Nikol/` | `Уроки_Николь.json`, `Занятия_Николь.json`, `Продлёнка_Николь.json` | `Nikol/nikol.js:485-513` |

**Вывод:** любая новая логика, читающая занятия, должна брать глобал `PERSONAL`, а не файл
`zanyatiya.json`. Файл в корне не источник истины.

### Типы занятий

- Встроенные: `school` (Урок/Уроки), `personal` (Занятие/Занятия), `extended` (Продлёнка).
- Кастомные: `CUSTOM[имя]`, ключ = имя типа, создаются свободным вводом в модалке.
- `resolveTypeKey()` маппит введённое имя на ключ, знает множественные формы и сравнивает
  кастомные ключи без учёта регистра. При правке типов учитывать это.
- **Продлёнка — только пн–пт** (`dayIdx <= 4`). Правило реализовано в трёх местах:
  `renderDayLessons`, `hasExtended`-проверки `renderAll` (мобильная и десктопная ветки),
  `focusEvents` (в обеих копиях `script.js` — блок события и прогресс-бар в hero).
  Менять **синхронно во всех трёх и в обеих копиях** `script.js`, иначе на сб/вс появятся
  пустые панели, пропадут шутки или «Сейчас: Полдник» в выходной.
- Сб/вс — «пустые» дни: только шутка дня (`renderWeekendMsg` + `SAT_MESSAGES`/`SUN_MESSAGES`).

### Блок события (`.focus`)

Живёт внутри `.day-hero` во всех трёх страницах (`index.html`, `assets/index.html`, `Nikol/index.html`).
Показывает **любое** событие дня — урок, занятие, кружок, факультатив, продлёнку, а не только уроки.

- Разметка: `.focus > .focus-topline (.eyebrow + .live-dot + #focusEyebrow)`, `.focus-title#focusTitle`,
  `.status#status`, `.progress-wrap > .progress-caption > #progressLabel`, `.progress-bar > #progressFill`.
- Орбита — `.focus-art` (потомок `.day-hero`, **не** потомок `.focus`) с `.orbit-stage` внутри.
  `.focus-art` повторяет бокс `.day-hero::before` (`--circle`, `right:5% top:5px`), а `.orbit-stage` —
  квадрат `70.71%` от него (вписанный квадрат круга). Все размеры считаются от `--circle`.
  Менять круг — только через `--circle`, иначе круг и орбита разъедутся.
- Логика в `script.js` (обе копии, идентична): `focusEvents(today)` собирает события и
  **сортирует по времени начала** — без сортировки «следующее» окажется не следующим, потому что
  источники отдают события вперемешку; `resolveFocus(events, minute)` → состояние
  `current`/`next`/`past`/`free`; `focusProgress(events, minute)`; рендерят `renderStatus()` и
  `renderProgress()` (имена менять нельзя — их зовут `init()` и `startEngines()`).
- Обратный отсчёт живой через `data-cd`/`data-cd-end` — их обновляет `updateCountdowns()`
  в `engines.js`. Не переносить текст в JS-строку, если он должен тикать.
- `renderStatus`/`renderProgress` обязаны вызываться и из `onToggle()` во всех трёх базах.
- `Nikol/nikol.js` — своя версия на `getItemsForDay()`: у неё события уже отсортированы и помечены
  `type`, объединённые имеют `type: "merge"`; диапазон берётся через `focusItemRange()`,
  подпись через `focusLabel()`, бейдж типа «Смешанно».

### Палитра: 4 слоя

`style.css` (и его копия в assets) содержит 4 набора: бирюза/индиго × светлая/тёмная.
Бирюза — текущая палитра по умолчанию и лежит в `:root` / `.dark`. Индиго (раньше перекрытая
бирюзой) возвращена под `body.palette-indigo` / `body.palette-indigo.dark`.
Слои: палитра приложения → `--hero-*` (цвета `.day-hero`) → `--focus-*` (блок события).
`--focus-signal` намеренно «чужой» hue: индиго в бирюзе, бирюза в индиго.

Переключатель: `setPalette(name)` в каждой из трёх кодовых баз, класс на `<body>`,
`localStorage` ключ `palette` (в `Nikol/` — `nikol_palette`, свой namespace).

### Android

- Kotlin 100%, Java-файлов нет. Java 17.- minSdk 26 (Android 8.0), targetSdk 35, compileSdk 35.
- Зависимости: `core-ktx`, `appcompat`, `material`, `webkit`, `swiperefreshlayout`, `work-runtime-ktx`.
- WebView грузит `https://appassets.androidplatform.net/index.html`.
- `AndroidBridge` (`@JavascriptInterface`): `exportTxt`, `showToast`, `showConfirm`, `syncReminders`,
  `getNotificationStatus`, `openRingtonePicker`, `playRingtone`, `stopRingtone`.
- Импорт/экспорт JSON — внутри `MainActivity.kt` (`importJson`, `exportPart`, `exportFullJson`);
  имена экспортируемых файлов: `uroki.json` (schedule), `zanyatiya.json` (personal),
  `prodlenka.json` (extended). В вебе импорта нет.
- Сборка: `gradle assembleDebug` из `android\`.

## 9. КОДИРОВАНИЕ И WINDOWS (среда: Windows, PowerShell 5.1)

- **UTF-8 без BOM.** `Set-Content` и `Out-File` в PowerShell 5.1 пишут BOM — не используй их
  для записи файлов проекта. Правь файлы инструментами редактирования, а не конвейером в консоль.
- **Кириллица через консоль не читается.** Вывод `rg`, `Get-Content`, `Select-String` и файлов с
  кириллицей в имени приходит битым (mojibake) — это не файл сломан. Для чтения и правки русских
  строк используй инструменты чтения/редактирования файлов, не консольный вывод.
  Ручной ввод кириллицы в heredoc/консоли даёт гомоглифы — бери строки из реальных файлов.
- Русский текст: HTML-контент, JSON-данные, Toast-сообщения.
- Идентификаторы, имена переменных, комментарии в Kotlin/JS — английский.
- В PowerShell 5.1 `&&` не работает — используй `; if ($?) { ... }`.
- В PowerShell 5.1 регулярные выражения с `'` внутри кавычек ломают парсер — используй
  инструмент поиска по содержимому, а не ручные регулярки в командной строке.

- Общение с пользователем — русский. Тон: сжатый, точный, без воды. Один абзац лучше простыни.

## 11. ИНСТРУМЕНТЫ

### Graphify — обязательный первый шаг

Граф знаний проекта: `graphify-out\graph.json` (в `.gitignore`).
CLI: `C:\Users\Viktor\.local\bin\graphify` (`uv tool install graphifyy`).
В opencode доступен MCP-инструмент `headroom_compress` и скилл `graphify` — используй их,
они надёжнее длинных однострочных `python -c` (те ломаются на Windows).

Жёсткое правило: **перед `read`/`grep`/`task` — сначала `query graph.json`.**

```powershell
# есть ли граф
Test-Path graphify-out\graph.json
# построить/обновить
graphify . --code-only
```

Что делать, если граф недоступен (нет MCP, нет `python`, нет файла):

- `graphify-out\graph.json` есть → читай его напрямую (это не «чтение исходников»).
- графа нет и построить нельзя → **спроси пользователя**, можно ли читать исходники напрямую.
  Молча нарушать правило нельзя; молча игнорировать его — тоже.

Разрешено без отдельного `query`:

- читать файл, путь к которому уже известен из `graph.json` или из задачи пользователя;
- `grep` в одном конкретном файле, если `graph.json` указал этот файл;
- запуск `graphify . --code-only` для обновления графа;
- после правок — обновить граф (`graphify . --code-only`).

Формат `graph.json`:

- узлы: `{id, label, source_file, source_location, community_name, ...}`
- рёбра (`links`): `{source, target, type}` — типы: `calls`, `imports`, `defines`, `returns` и др.

### Headroom — сжатие контекста

CLI: `C:\Users\Viktor\.local\bin\headroom` (`uv tool install "headroom-ai[mcp]"`), MCP зарегистрирован.

- Сжимай большие выводы поиска, логи и JSON перед анализом.
- **Не сжимай то, что собираешься редактировать**, и не сжимай список файлов/строк,
  по которым будешь делать правки. Сохраняй хеш сжатия, оригинал восстанавливается по нему.
